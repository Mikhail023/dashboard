# Расширение Dashboard

## Анализ до изменений

Electron main владеет SQLite, авторизацией, экспортом, таймером и уведомлениями.
Preload предоставляет единственный типизированный bridge; IPC проверяет сессию,
отправителя и входные данные через Zod. Repository выполняет миграции транзакционно.
React использует Zustand со snapshot, ленивые страницы и навигацию page/selected.
Общие Modal, EntityForm, Search и CSS tokens сохраняются и расширяются.
TipTap отвечает за заметки с автосохранением; задачи и календарь уже используют
native drag/drop. Настройки хранятся в SQLite. Проекты уже связаны с задачами,
заметками, событиями, транзакциями, счетами и записями времени через project_id.
Календарь уже отображает дедлайны задач без создания событий. Поиск и ⌘K едины,
но требуют общего расширяемого слоя фильтрации и команд.

Миграция 002 добавляет поля повторов, tasks.note_id, Inbox, бюджеты, цели и факты
выполнения повторяющихся задач. Она не удаляет и не пересоздаёт существующие таблицы.
Связи 1:N остаются типизированными внешними идентификаторами с проверкой Repository;
для связи Task→Note используется note_id. Это расширяет существующую модель.
Вычисляемые сводки, timeline и виртуальные повторы в БД не сохраняются.

## Реализованные функции

- Локальный Smart Input: шесть типов записей, русский разбор дат/времени, суммы с
  разделителями, RUB/USD/EUR, подсказка категории, предпросмотр и редактируемая форма.
  Недостающая распознанная категория создаётся вместе с операцией в транзакции.
  Доступ из верхней панели и по ⌘⇧Space. Облачные API не подключены.
- Task → Note и существующие project_id объединяют модули. Из заметки можно создать
  задачу, из задачи открыть заметку, из проекта — связанные задачи, заметки, события,
  операции и счета. Дедлайны задач отображаются календарём без копий событий.
- Один search service и одна палитра ⌘K для поиска и команд. Есть фильтры типа, даты,
  проекта, тега, статуса; команды создания, перехода, настройки дашборда и цвета.
  Стрелки, Enter, Home/End, Escape, Tab; результаты прокручиваются к выделению.
- Smart Dashboard: сегодня, просрочено, события, активные проекты, последние заметки,
  финансы/расходы, бюджеты, цели, Inbox, статистика дня. Старые виджеты и KPI сохранены.
  Дополнительные виджеты изначально скрыты, кроме задач на сегодня.
- Grid: drag/drop, клавиатурные кнопки порядка, размеры S/M/L, скрытие/возврат,
  переименование, сброс. В S остаётся ключевое значение, M показывает детали, L Finance
  показывает категории с диаграммой и бюджеты. Настройки сохраняются в прежнем settings.
- Inbox: создание, редактирование, необработанные/обработанные, счётчик. Конвертация
  в Note/Task/Project атомарна и защищена от повторного нажатия; исходник сохраняется.
- Повторы задач и событий: daily/weekly/monthly/yearly/weekdays/selected weekdays,
  интервал, окончание серии. В форме дни выбираются флажками. В БД одна серия; реальные
  выполнения задач записываются в task_completions. Календарь позволяет отметить
  конкретный повтор. Учтены последние дни месяца и 29 февраля.
- Бюджеты по категориям или общий месячный бюджет: spent, remaining, percentage,
  progress, превышение. Нет смешивания валют и двойного счёта переводов.
- Финансовые цели: создание, редактирование целевой и накопленной суммы, прогресс,
  завершение. Пример MacBook 180000/250000 отображается как 72%.
- Light/Dark/System сохранены. Orange, Blue, Purple, Green, Red, Graphite и custom
  используют CSS variables для акцентов, не прозрачность всего интерфейса.
- Daily Timeline: любой прошлый день, реальные created_at/completed_at, расписание
  событий, финансовая дата. Клик открывает сущность; сводки вычисляются на лету.
- Daily Brief: три приоритетных задачи, ближайшее событие, просрочено, остаток бюджета,
  главный проект. «Начать день» открывает Focus: главная/следующие задачи, событие,
  прогресс. После 18:00 сводка автоматически становится итогами дня.
- Notes → Markdown/PDF, Tasks → CSV/JSON, Projects → JSON, Finance → CSV, вся система
  → JSON v2. Старый JSON v1 поддерживается; timestamps сохраняются при импорте.
- Перед import/restore создаётся копия в SafetyBackups. SQLite backup сначала
  мигрируется и проверяется во временном файле. Только после проверки и подтверждения
  в существующем диалоге восстановления активный файл заменяется атомарным rename.
  Исходный backup не изменяется; при ошибке установки предусмотрен откат из safety.

## Зависимости и архитектура

Новых dependencies нет. Использованы имеющиеся date-fns, Zod, RHF, Zustand,
better-sqlite3, Playwright, Vitest и Electron. Main/preload/renderer границы,
SQLite, авторизация, таймер, счета-фактуры, TipTap и ленивые страницы сохранены.
Новый проект, второй store, второй Modal, второй search или второй database service
не создавались. Старый event occurrences делегирует общему движку повторов.
Backup остаётся полным, экспорт отдельных таблиц — переносимым представлением данных.

## Ограничения

- Локальный parser — расширяемые правила, не универсальная языковая модель.
  Поддерживает описанные примеры, относительные даты, дни недели, ISO и DD.MM.YYYY;
  неоднозначный текст необходимо проверить в предпросмотре. Счёт нужной валюты
  пользователь создаёт в Finance; автоматической конвертации валют нет.
- Поиск учитывает дату и выполнение конкретного повтора. Теги есть у
  заметок/Inbox и наследуются задачей от связанной заметки. При выборе повтора
  из поиска открывается форма всей серии; исключения отдельных событий не поддерживаются.
- Список Tasks показывает всю историю, следующие 7 дней и ближайший
  последующий повтор каждой серии. Focus и просроченные учитывают всю историю.
  Произвольные будущие даты доступны через Calendar. Изменение параметров
  события меняет серию; исключения событий/RRULE не добавлены.
- Timeline не может восстановить историю до существующих timestamps. Для операции
  с прошлой финансовой датой и неизвестным временем показывается «Весь день»;
  события отражают расписание, а не факт посещения. Прогресс проекта — текущий.
- Итоги дня вычисляются после 18:00, обновляются раз в минуту, доступны при открытии
  приложения; отдельного фонового демона и сохранённых снимков сводок нет.
- JSON отдельных таблиц не является полным backup и не подаётся в общий импорт.
- Сохранены прежние ограничения: SQLite не зашифрован, нет Apple notarization,
  Touch ID не тестировался на физическом сенсоре, Intel не запускался на Intel Mac.

## Повторный аудит — 1.1.1

Исправления выполнены в существующей архитектуре. Новых зависимостей, таблиц,
миграций и исходных файлов не добавлено; migrations/001 и 002 не изменены.

### Исправленные ошибки

- Убраны ограничения 7/30 дней для истории повторов и скрытый предел 10 000
  результатов генератора. Невыполненные старые повторы учитываются в задачах,
  Focus, Dashboard и уведомлениях. Ближайшие редкие события находятся за
  пределами 30 дней; отдалённые будущие серии доступны в списке задач.
- Поиск даты учитывает правило повторения, границу окончания и выполнение
  выбранного экземпляра. Сохранён единый сервис для поиска и палитры команд.
- Канбан отменяет выполнение конкретного повтора. Раскрытие одной строки
  больше не раскрывает одновременно всю серию. В форме серии пояснено,
  где отмечать отдельные выполнения; ошибочное завершение master-записи отклоняется.
- Автосохранение заметок отправляет только изменённые поля, не затирая теги
  и проект старой копией записи. Убраны повторные записи при уходе из редактора
  после успешного сохранения. Экспорт/создание задачи прекращаются при ошибке сохранения.
- JSON-импорт сохраняет удалённые операции вместе с удалённым счётом.
- Отклоняются невозможные календарные даты; слишком большая относительная
  дата не ломает Smart Input. Время события сравнивается хронологически с учётом
  часового пояса. Месяц финансов и дата оплаты определяются по локальному времени.
- Сводка дня различает сегодняшний повтор и выполненный сегодня старый повтор.
- В форме убраны дубли пустых options, категории фильтруются по типу операции,
  целочисленные интервалы имеют целочисленный шаг.
- Ответ ранее начатого обновления состояния не возвращает данные на экран блокировки.

### Оптимизация и интерфейс

- Календарь вычисляет повторы один раз на диапазон вместо каждой ячейки.
- Поиск и Timeline используют Map для связей вместо повторного линейного поиска.
- Аналитика Dashboard группирует реальные timestamps завершения вместо семи
  полных вычислений Timeline. Расходы по категориям агрегируются один раз,
  включая расходы без категории. Суммы агрегируются в копейках.
- Завершение повтора читает одну задачу из SQLite; фоновые напоминания читают
  только события вместо всех таблиц. Используется прежний Repository.
- Таймер не обновляет React каждую секунду, когда остановлен или на паузе.
- S/M/L адаптируют количество записей и подробности: списки задач/проектов/
  событий/заметок, история Inbox, статистика дня, бюджеты/цели, аналитика,
  расходы и история таймера. Исходная палитра и общий дизайн сохранены.
- TypeScript с noUnusedLocals/noUnusedParameters не нашёл неиспользуемого кода.

## Версия 1.2.0 — Habits / Daily Goals

Добавлена единая система привычек в текущий Dashboard без отдельного приложения.

### Миграция и модель

Добавлена [003_daily_goals.sql](/Users/mihail/Downloads/03/migrations/003_daily_goals.sql).
Она создаёт `daily_goals` и `daily_goal_entries`: первая таблица хранит название,
тип (`boolean` или `quantitative`), норму, единицу, иконку, собственный цвет,
связанный проект и ключевые слова Smart Input. Вторая содержит только значение
за конкретный день. Проценты и статистика не сохраняются.

`progress = value / target_value`. Серии и completion rate рассчитываются из
отмеченных дней: текущая серия допускает ещё не завершённый сегодняшний день,
длиннейшая серия ищет непрерывные завершённые даты, completion rate — долю
завершённых дней от даты начала привычки до сегодня.

### Интерфейс и связи

- [Habits.tsx](/Users/mihail/Downloads/03/src/renderer/pages/Habits.tsx) добавляет
  раздел «Привычки» с периодами 3 месяца, 6 месяцев и годом.
- [HabitHeatmap.tsx](/Users/mihail/Downloads/03/src/renderer/components/HabitHeatmap.tsx)
  строит календарную heatmap; плитки используют уровни 0, 1–49, 50–99, 100 и
  >100%. Для перевыполнения сохранён яркий цвет и маленькая точка без glow.
- Цвет вычисляется из `Daily Goal.color`, а при пустом значении — из существующего
  `--primary` акцента приложения. Уровни интенсивности выводятся через CSS
  `color-mix`, без разрозненных жёстко заданных цветов.
- [HabitWidget.tsx](/Users/mihail/Downloads/03/src/renderer/components/HabitWidget.tsx)
  подключён к существующей сетке: S показывает имя, иконку, streak и 14 дней;
  M — три месяца и текущий прогресс; L — год, месяцы, все показатели и прогресс.
- Smart Input понимает «Сегодня читал 20 страниц», «Учился 1 час 30 минут» и
  «Тренировка выполнена», предлагает подходящую привычку и сохраняет значение
  локально. Отметки отображаются и редактируются из Daily Timeline.
- Привычка может быть привязана к проекту и видна на его странице.
