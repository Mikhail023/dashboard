# Публикация обновлений

Общий код находится в `src/`, настройки платформ — `mac/` и `windows/`.
GitHub Actions проверяет обе ОС, собирает macOS arm64/x64 и Windows x64,
запускает smoke-проверку собранных приложений и сохраняет установщики как артефакты.

## Выпустить версию

1. Внесите изменения и обновите `docs/release-notes.md`.
2. Выполните `npm version patch` (либо `minor` / `major`): версия и тег должны совпадать.
3. Выполните `git push origin main --follow-tags`.
4. Дождитесь зелёного workflow **Build, test and release**.

Публикация происходит только для тегов `v*`, после всех проверок. Обычный push
ветки проверяет код и создаёт артефакты, но не предлагает пользователям непроверенную версию.
Релиз сначала создаётся черновиком; после загрузки всех установщиков, blockmap и
`latest.yml` / `latest-mac.yml` он публикуется целиком. macOS-манифест объединяет обе архитектуры.
Исправления уже опубликованного релиза выпускайте новым увеличенным номером версии.

## Как пользователь получает обновление

Обновления проверяются в main process через `electron-updater` при запуске готового
приложения и каждые 6 часов. Ручная проверка: меню Dashboard → Проверить обновления.
Офлайн-ошибки при автоматической проверке не мешают работе приложения.
Загрузка и установка требуют выбора пользователя. Перед перезапуском сохраняется
таймер и создаётся SQLite backup. Пользовательские данные не включены в установщики.
В renderer по-прежнему запрещены внешние сетевые запросы.

Неподписанная macOS-сборка показывает предложение скачать DMG; автоматическая
установка на macOS требует Developer ID. Windows NSIS поддерживает установку
обновления после подтверждения. Первую версию с обновлениями нужно установить вручную:
версии до 1.3 не могут сами получить новый механизм.

Публичные обновления требуют публичного репозитория релизов. Нельзя встраивать
GitHub token в клиент. Приватный репозиторий исходников можно оставить приватным,
вынеся релизы в отдельный публичный репозиторий и изменив publish config и releasesURL.

## Подписи

Текущий workflow собирает неподписанные приложения. Для macOS настройте защищённые
GitHub Secrets CSC_LINK, CSC_KEY_PASSWORD и данные нотариализации Apple; уберите
`identity: null` и `CSC_IDENTITY_AUTO_DISCOVERY: false`, настройте notarize и добавьте
`--config.extraMetadata.dashboardMacAutoUpdate=true`. Для Windows подключите сертификат
подписи к electron-builder. Секреты никогда не сохраняйте в git или приложении.
